# 两台电脑同步手册

> 目标：上班电脑和家里电脑共用同一个 DSH 工作区，文件、资料、对话记录都能互相看见。
> 更新：2026-10-27

## 0. 一句话流程

```
上班前 / 开机后：  git pull
干活（让 DSH 改文件）
收工前 / 关机前：  git add -A && git commit -m "描述" && git push
```

**同一时间只有一台电脑在改**，就不会有冲突。两台同时改了同一文件，才会冲突（处理见第 5 节）。

## 2. 新电脑第一次配置

### 2.1 装 Git
1. 下载：`https://mirrors.tuna.tsinghua.edu.cn/github-release/git-for-windows/git/LatestRelease/`（挑 `Git-*-64-bit.exe`）或 `https://git-scm.com/download/win`
2. 安装一路默认即可
3. 验证：打开 PowerShell 输入 `git --version` 有版本号

### 2.2 拷令牌
把旧电脑的 `D:\dsh-workspace\_tools\github-token.txt` 用微信/密码管理器/U 盘传过去。
（`_tools` 不进仓库，所以不会自动同步。）

### 2.3 克隆仓库
```powershell
cd D:\
git clone https://github.com/PoSui/dsh-workspace.git
```

### 2.4 配置身份（一次即可）
```powershell
cd D:\dsh-workspace
git config user.name "PoSui"
git config user.email "50458979+PoSui@users.noreply.github.com"
git config core.quotepath false      # 中文文件名正常显示
git config core.autocrlf false       # 别自动改换行符，避免假改动
```

### 2.5 让 git 记住令牌（一次即可）
```powershell
git config credential.helper store
git push
# 提示 Username: PoSui     Password: 粘贴 token（ghp_ 开头那串，不是登录密码）
```
成功一次后，令牌就存进 Windows 凭据（`%USERPROFILE%\.git-credentials`）。

> 如果只想临时用：把远程地址写成
> `git remote set-url origin https://PoSui:令牌@github.com/PoSui/dsh-workspace.git`
> （令牌会明文存在 `.git/config` 里，私有电脑可接受。）

## 3. 日常怎么用

### 3.1 开工
```powershell
cd D:\dsh-workspace
git pull
```
把另一台电脑的改动拉下来。看到 `Already up to date.` 就是没新东西。

### 3.2 干活
正常让 DSH 改文件。想看改了什么：
```powershell
git status          # 哪些文件变了
git diff            # 具体改了什么
```

### 3.3 收工
```powershell
git add -A
git commit -m "一句话说清这次改了什么"
git push
```

### 3.4 建议习惯
- **出门前**（下班/关机）一定 push；
- **回家/开机**先 pull 再干活，否则两台各改一份会冲突；
- commit 信息写清楚，例如 `更新决策台账：定投额度`、`补充绿电绿证政策梳理`。

## 4. 哪些东西进仓库

**进**：markdown、文档、图片、drawio、代码、会话记录摘要。

**不进**（`.gitignore` 已排除）：
- `_tools/`（git 令牌、同步脚本、临时探测脚本）
- `*.zip`（交接包等备份）
- `node_modules/`、日志、系统垃圾、`.idea/`、`.tmp/`

> **2026-10-28 起**：`.dsh/`（技能包，约 1.7MB / 114 文件）也纳入版本管理，两台机器拉下来即有一致的技能。若某台机器自己的技能更多，注意覆盖问题。

**大文件限制**：GitHub 单文件 >50MB 会警告、>100MB 直接拒绝。真有大文件（视频、安装包、jar 包）：
- 放 `_tools/` 或网盘，不提交；
- 或者用 Git LFS（`git lfs track "*.jar"`），但免费额度只有 1GB 存储 / 1GB 流量，慎用。

## 5. 冲突了怎么办

症状：`git pull` 或 `git push` 报 `CONFLICT` / `rejected` / `non-fast-forward`。

```powershell
git pull            # 先拉，让 git 把冲突标出来
git status          # 列出「双方都改了」的文件
```
打开冲突文件，会看到：
```
<<<<<<< HEAD
你本机的版本
=======
另一台电脑的版本
>>>>>>> origin/main
```
手动改成你要的最终内容（删掉 `<<<<<<<`、`=======`、`>>>>>>>` 三行），然后：
```powershell
git add -A
git commit -m "合并冲突：xxx"
git push
```

**简单原则**：两台机器不要同时改同一个文件；内容冲突时，以“更晚知道信息的那台”为准，改完再提交。

## 6. 这台机器（上班电脑）的特殊情况

沙箱里的 DSH 运行在受限账户下，有两条限制：

1. **不能写用户目录**（`C:\Users\Administrator`），所以 git 凭据、SSH 都得你手动配；
2. **`github.com` 的 HTTPS 直连不稳**（TCP 能连、TLS 常被重置）。开了梯子就正常——本仓库第一次推送就是开梯子后 `git push` 成功的。

如果哪天梯子没开、又急着推，可以用 `_tools/` 里的兜底脚本（走 `api.github.com`，这个域名国内直连可用）：

```powershell
# 1) 本地提交
git add -A; git commit -m "说明"

# 2) 导出 HEAD 文件清单
git ls-tree -r HEAD | Out-File -Encoding utf8 _tools\head-tree.txt

# 3) 用 API 推送（$env:GH_TOKEN 要设成令牌）
$env:GH_TOKEN = 'ghp_...'
node _tools\gh_push.js _tools\head-tree.txt "提交说明" D:\dsh-workspace
# 输出 PUSH_OK <sha> 即成功
```
注意：API 推送后本地和远端的提交历史不是同一条线，**下次恢复梯子时用 `git push --force` 把本地历史推上去对齐**，或者干脆以远端为准重新 `git clone`。

### 6.1 2026-10-28 办公室机实测配置（已验证可推送）

实测结论：梯子（系统代理 `127.0.0.1:4780`）开着，但 DSH 沙箱里 git 仍有两个坑：

1. **DNS 被污染**：`github.com` 解析到 `127.0.0.1`，直连必挂 → 必须走代理；
2. **schannel TLS 不可用**（`SEC_E_NO_CREDENTIALS`）→ 必须用 openssl 后端。

本仓库 `.git/config` 已配好（一次性）：

```powershell
cd D:\dsh-workspace
git config http.proxy http://127.0.0.1:4780
git config http.sslBackend openssl
git config user.name "PoSui"
git config user.email "50458979+PoSui@users.noreply.github.com"
git config core.quotepath false
git config core.autocrlf false
git config credential.helper "store --file=D:/dsh-workspace/_tools/.git-credentials"
```

- 沙箱内 `sh.exe` 起不来 → credential helper 用不了；**在 DSH 会话里推送**要用带 token 的临时 URL：
  ```powershell
  git remote set-url origin "https://<token>@github.com/PoSui/dsh-workspace.git"
  git push origin main
  git remote set-url origin https://github.com/PoSui/dsh-workspace.git
  ```
- 在**普通 PowerShell**里（非沙箱）可以直接 `git push`，凭据走 `_tools/.git-credentials`。
- `git init` 默认分支是 master，记得 `git branch -m main` 再推。
- 令牌文件：`_tools/github-token.txt`；凭据文件：`_tools/.git-credentials`（两者都不进仓库）。

## 7. 对话记录（让另一台电脑知道我们在干什么）

`对话记录/` 里有：

| 文件 | 作用 |
|---|---|
| `对话摘要_*.md` | 人读的纪要：这轮聊了什么、做了什么、还欠什么 |
| `还原说明.md` | 怎么把会话文件装回 DSH，恢复完整对话 |
| `会话文件/*.jsonl.zstd` | DSH 原始会话记录（二进制，DSH 自己读） |

**另一台电脑拉下来后**：
1. 先看 `对话摘要_*.md`（30 秒知道上下文）；
2. 想让 DSH 也“记得”完整对话：按 `还原说明.md` 把 `.jsonl.zstd` 放回 `C:\Users\<你>\.dsh\sessions\` 对应目录，重启 DSH 即可在会话列表里看到。

> 会话文件是快照：每次 push 前的样子。要最新记录，就在那台机器上重新导出/复制一次。

## 8. 常见问题

| 症状 | 原因 | 处理 |
|---|---|---|
| `fatal: Authentication failed` | 令牌错/过期/没存 | 重新 `git config credential.helper store`，push 时粘贴新令牌 |
| `schannel: ... SEC_E_NO_CREDENTIALS` | 沙箱里 TLS 走了系统证书 | 开梯子重试；或 `_tools` 的 API 脚本 |
| `failed to push some refs / rejected` | 远端有你本地没有的提交 | 先 `git pull --rebase`，再 push |
| `unable to unlink old 'x'` | 文件被占用或只读 | 关掉打开该文件的程序（drawio/Office），再操作 |
| 中文文件名显示成 `\344\272...` | quotepath 默认开 | `git config core.quotepath false` |
| 每次 diff 都有大量“改动” | 换行符被转换 | `git config core.autocrlf false`（仓库已设） |
| 误删文件想找回 | 已提交过 | `git checkout -- 文件路径` 或 `git log -- 文件` 找到旧版本 |

## 9. 命令速查

```powershell
git pull                      # 拉最新
git status                    # 看状态
git diff                      # 看改动
git add -A                    # 全部暂存
git commit -m "说明"           # 提交
git push                      # 推送
git log --oneline -10         # 最近 10 条提交
git log --oneline -- 文件      # 某文件的历史
git checkout -- 文件           # 撤销未提交的改动
git restore --staged 文件      # 取消暂存
```
