## 2. 当前能力边界（v19）

### 2.1 能

- 实时看钱（今天/本期/时薪族）、按发薪日看账期、日历补记整日类型、多目标攒钱（可改金额）、两套 CSV 导出、跨天自动收尾、夜班与调休补班。

### 2.2 不能（能力缺口，按影响排序）

| 场景 | v19 现状 | 影响 |
|---|---|---|
| 今天只上了 4 小时就下班 | 只能实时计时到下班；想"事后补录半天"没有入口 | 实际工时被低估，本期金额偏低 |
| 中途离开 1 小时（开会/外出） | 没有暂停按钮；只有"继续计时"会把离开时间也算进去 | 数字偏高，但 confirm 已声明，属已知取舍 |
| 换电脑/清缓存 | 没有备份/导入；CSV 只能出不能回 | 历史全丢，无法恢复 |
| 手机上看一眼 | 无移动端、无同步 | 只能到电脑前看 |
| 2027 年及以后 | 假期表只有 2026；跨年账期标题有提示，但 2027-01-01 仍按日薪计 | 数字偏高，标题提示是唯一防线 |
| 看趋势/对比 | 只有单日明细与本期合计，没有折线/月视图 | 复盘靠脑补 |
| 桌面常驻小窗 | 代码和 CSS 都在，**页面没有按钮**，`?mini=1` 也没处理 | 承诺的用法用不了 |

## 3. 候选需求池（按性价比排序）

成本口径：**S** ≤ 1 小时、**M** 2–4 小时、**L** ≥ 1 天（单人维护）；性价比综合"坏掉的风险 × 用户实际感知"。

| # | 需求 | 解决什么 | 成本 | 性价比 | 结论与理由 |
|---|---|---|---|---|---|
| N1 | **测试台改为"以 HTML 为准"**：ids 由 HTML 自动生成；harness eval HTML 内脚本；页面元素缺失即报错 | D2——现在绿的是 JS 而不是产品 | M | 极高 | **立即做**。小窗消失 4 个版本没被发现，就是因为这条；不做它，后面每条修复都无法证明真的生效 |
| N2 | **恢复小窗**：页面加"小窗"按钮；`?mini=1` 时给 `body` 加 `mini` 类；430×380；Esc 或按钮回主窗 | D1——承诺的核心用法缺失 | S | 极高 | **立即做**。代码 90% 已在（CSS + `window.open`），只缺入口与开关；配合 PowerToys 置顶才成立 |
| N3 | **去重 + 清死代码**：`btnMini` 绑定移出 render；删重复赋值、`renderTables`、死函数、死 CSS | D3/D4——为 N2 让路 | S | 高 | **立即做**（与 N2 同一提交）。否则 N2 一上线就带监听器泄漏 |
| N4 | **存储失败提示**：`saveSettings`/`saveRecords` 包 try/catch，失败弹明确文案并保留内存态 | D7——静默丢数据最伤 | S | 高 | **立即做**。本地存储工具最怕"以为存了" |
| N5 | **补录"当天工时"**：日历菜单加"输入工时"，`earned = 小时 × 当天时薪`，`dayValue` 优先取它 | D8——半天班/外勤是高频真实场景 | M | 高 | **v20 做**。比"再加一种整日倍率"有用得多；需要定口径：工时上限、是否扣午休（建议照 `paidHours` 扣除） |

| N7 | **补 v19 新功能断言**：目标金额点击修改、排序、✅、进度条 `<i>` | v19 三处改动 0 断言 | S | 高 | **立即做**（并入 N1）。否则下次改目标卡片又是盲改 |
| N8 | 2027 假期表占位（官方公布前保持提示） | D5 | S | 中 | 排期做：数据没出之前只保留提示，不硬编码猜测（不编造政策数据） |
| N9 | 真暂停按钮（用已有 `pauses` 字段，暂停期间不计钱） | D6——回滚口径不自然 | M | 中 | v21 做：会把"继续计时"的语义一起改，需要产品口径拍板（暂停 vs 回滚二选一还是并存） |
| N10 | 目标达成归档（达成的目标折起/进历史） | 目标多时列表变长 | S | 中 | 后置：目前目标 ≤3 个，列表不痛 |
| N11 | 主数字 4 位小数（或每秒末两位弱化显示） | D10——"看着涨"的爽感 | S | 中 | 可选：4 位小数会让主数字变长、可读性下降；建议只在"每秒"卡片保留 4 位，主数字维持 2 位 |
| N12 | 月视图/趋势折线 | 复盘"这个月比上月多赚多少" | M | 低 | **不做**：数据密度低（每月 20 条），看一次就够；与"打开即见钱"的首屏优先级冲突 |
| N13 | 自动开始/自动存档（到点自动计时） | 免手动 | M | 低 | **不做**：忘关会污染金额，且没有暂停模型时无法纠偏；手动一次的成本低于信任成本 |
| N14 | 多端同步/账号/云 | 手机看 | L | 低 | **不做**：本地优先是产品前提（隐私：工资数据不出本机）；引入后端后所有原则都要重写 |
| N15 | 个税/社保/工资条精确核算 | 想知道到手 | M | 低 | **不做**：口径随城市/单位/专项扣除变化，产品无法保证正确；"不确定的钱不能显示" |
| N16 | 主题/皮肤/动画 | 好看 | S | 低 | **不做**：不解决核心问题，且会稀释"数字本身是主角" |
| N17 | 导出图片/对外分享战绩 | 社交 | S | 低 | **不做**：工资数据外发有隐私风险，且产品明确不对外发送 |

不做项的共性理由：这个产品的价值集中在"一眼看到在涨"和"数字可信"，任何不强化这两点的需求，成本再低也是净负担。

### 4.3 验收标准（可直接执行）

**自动化**

1. `node _tests\harness.js`：通过数 ≥ 110（现 100 + 新增 ≥10），失败 0，退出码 0。
2. `node _tests\harness_ext.js 牛马计时器_v20.html`：通过数 ≥ 45（现 40 + 新增 ≥5），失败 0。
3. 新增断言必须覆盖：HTML 中每个 `getElementById` 的 id 都存在（从 HTML 取，不读 `ids.json`）；`#btnMini` 存在且点击不抛错；模拟 `location.search="?mini=1"` 时 `document.body.classList` 含 `mini`；目标金额编辑后 `GOALS[0].amount` 变化且 ETA 重算；目标排序（达成项在未达成项之后）；`localStorage.setItem` 抛错时出现提示且页面不白屏。
4. 若保留 `ids.json`，增加一致性断言：`ids.json` 的 id 集合 == HTML 中 id 集合（否则失败并打印差集）。

**人工（浏览器真机，5 分钟）**

## 5. 维护约定（避免再次"绿着坏掉"）

1. **改 HTML 后必须重新抽取脚本到 `_tests\app.js`**，否则 harness 测的是旧代码。抽取命令（PowerShell）：
   `python -c "import re,io;h=io.open('牛马计时器.html',encoding='utf-8').read();io.open('_tests/app.js','w',encoding='utf-8').write(re.search(r'<script>([\s\S]*?)</script>',h).group(1).strip())"`
2. **`ids.json` 不再手写**：由 HTML 生成（`python` 一行正则即可），或直接废弃该文件。
3. 每版另存 `牛马计时器_vN.html`，主文件 `牛马计时器.html` 同步覆盖；版本号三处一致：`<title>`、brand、文件名（v12 的 title 写错就是教训）。
4. 改口径先改 `docs\产品说明.md` 的口径表，再改代码；改完跑两套测试 + 第 4.3 节人工清单。
5. 新增功能必须同时新增断言（哪怕只有 1 条），否则视为未完成。
